# スターの複数端末共有（設計メモ）

状態: WebDAV/S3 は `star-sync`、Google ドライブは `star-sync-google` ブランチで実装済み（未リリース）。実装は `lib/src/star_sync/` と設定画面の「スターの端末間同期」です。S3 互換は SeaweedFS 3.80（SigV4 認証あり）、WebDAV は Apache httpd 2.4.62 の mod_dav（Basic 認証あり）で動作を確認済みです。Google ドライブは OAuth クライアントが未登録のため、実際の Google アカウントでは未確認です。

連絡通知のスターを、同じユーザーの複数端末で共有します。More Better Gakujo 側ではサーバーを運用しません。標準の方法は「Google ドライブで同期」ボタンで、本人の Google ドライブにあるアプリ専用領域を使います。自分のサーバーを使いたい人向けに、WebDAV と S3 互換も詳細設定として残します。どの方式でも、端末ごとに暗号化したファイルを置き、他端末のファイルを読み込んでマージします。

## 確定した仕様

- **同期先は WebDAV と S3 互換の両方に対応する。** WebDAV は Nextcloud、NAS、InfiniCLOUD などでURLとパスワードだけで始められます。S3 互換は Cloudflare R2、Backblaze B2、MinIO などを想定します。
- **端末ごとに1ファイルを書き、共有ファイルを上書きしない。** 条件付き書き込み（`If-Match`）は AWS S3 などでは使えますが、R2 と B2 は公式資料で対応を確認できませんでした。ヘッダーを黙って無視する実装があっても変更が消えないよう、書き込み競合そのものが起きない構成にします。
- **同期するのは ID と件名だけ。** 本文、送信者、ジャンル、期間、掲載日は端末内にだけ保存します。他端末で付いたスターは件名だけで表示し、メッセージを開いたときに既存の `refreshStarredMessage` で本文を補います。
- **暗号化を必須にする。** 件名にも人名や手続き内容が含まれうるため、同期先の管理者から中身を読めない状態にします。鍵は WebDAV/S3 ではパスフレーズから作り、Google ドライブでは自動で作ってペアリングコードで別の端末に渡します。
- **同期は設定したときの学情アカウントに結び付ける。** 同期を使うにはログインIDの保存が必要です。ログインIDが変わったり消えたりしたら、通信もスター一覧の書き換えもせずに同期を止めます。元のIDに戻った後も、変更期間中のスターを同期に含めるか、前回の同期状態に戻すかを選ぶまで再開しません。アカウント変更前に確認待ちを保存し、同じアカウントのままで確認待ち解除に失敗した場合も確認画面を表示します。

## 同期先のファイル構成

利用者が指定したフォルダ（WebDAV のURL、または S3 のバケットとプレフィックス）の下に次を置きます。

```
<指定フォルダ>/more-better-gakujo/stars/
  keyring.json          共有の鍵情報（パスフレーズで包んだデータ鍵）
  devices/<deviceId>    端末ごとの暗号化ファイル
```

`deviceId` はインストールごとにランダム生成して端末内の安全な保存領域に置きます。バックアップには含めません。含めると、バックアップを復元した別端末が同じファイルに書き込み、単一書き込みの前提が崩れるためです。

## 端末ファイルの中身とマージ規則

設定の初回同期では、他端末に存在するキーはリモートの値を採用し、存在しないローカルのキーと復元で指定したキーは編集として同期します。

暗号化前の中身は次の形です。

```json
{
  "schema": 1,
  "deviceId": "…",
  "writtenAt": "2026-10-31T12:00:00Z",
  "clock": 42,
  "stars": {
    "1|23|456": {
      "title": "…",
      "starred": true,
      "starredAt": "2026-10-30T09:00:00Z",
      "clock": 41,
      "deviceId": "…"
    }
  }
}
```

- **1件ごとに勝者を決める。** 同じ ID のレコードは `clock`（ランポート時計）が大きい方を採用し、同じ値なら `deviceId` の辞書順で決めます。端末の時計がずれていても結果が変わらないよう、壁時計の時刻は判定に使いません。
- **削除は削除マーカーとして残す。** マーカーは (clock, deviceId, id) の新しい順に最大1000件を保持し、件名を空にします。古いマーカーが上限で消えた後は、オフライン端末からスターが復活する場合があります。
- **上限300件は全端末で同じ規則で切る。** マージ後は starredAt の新しい順、同時刻なら ID の昇順に300件残し、超過分はこの端末の新しい削除マーカーに変えます。
- **端末内の本文を消さない。** マージで変わるのはスター状態と件名だけです。勝者の件名が空なら端末内の件名を残します。
- **各端末は自分のマージ結果を書く。** 他端末の内容を取り込んだ状態で自分のファイルを書くので、使われなくなった端末のファイルが残っても害はありません。設定画面から古い端末のファイルを削除できるようにします。

`GakujoActivityStore` の既存操作との対応は次のとおりです。

| 既存操作 | 同期上の扱い |
|---|---|
| `toggleStarredMessage` / `upsertStarredMessage` / `removeStarredMessage` | 利用者の編集として `clock` を進める |
| `refreshStarredMessage`（詳細表示で中身を補う） | 端末内の補完なので `clock` を進めない |
| `replaceStarredMessages`（バックアップ復元） | 復元したスターは新しい編集として追加・更新し、バックアップにないスターは削除扱いにしない |
| `replaceStarredMessages(const [])`（データをすべて削除） | 先に同期を無効にし、空の一覧を他端末への削除として伝えない |

実装では各操作に同期処理を差し込まず、同期のたびに端末内のスター一覧と前回のマージ結果を比べて、この端末での追加・削除を導きます（`reconcileLocalStars`）。上限300件で端末内から押し出されたスターは、削除として扱いません。

## 同期の流れ

1. `devices/` を一覧する。
2. 前回から変わったファイルだけを取得する（ETag や更新日時を端末内に記録して比較）。
3. ヘッダーの鍵 ID が現在の鍵と異なるファイルは、リセット端末の旧鍵掃除を除き復号・削除せず、警告件数に含めずにスキップする。その他は復号して認証タグを検証し、形式不正・認証失敗・アカウント不一致のファイルは残してスキップ件数を警告表示する。旧鍵掃除以外では、利用者が「同期データをリセット」（全端末のファイルと鍵ファイルを消す）か、端末一覧から明示的に削除した場合に削除する。
4. 端末内のスターとマージし、端末内の保存領域へ書き戻してから同期状態を保存する。保存に失敗した場合も、ID とスターを付けた日時が既知の記録と一致すれば新しい編集として扱わないが、バックアップ復元で削除マーカーと一致したスターは新しい編集として復活させる。
5. 自分のファイルの内容が変わった場合だけ書き込む。

同期のきっかけは、起動時、アプリに戻ったとき、スターを付け外ししてから約5秒後、設定画面の手動同期です。通信に失敗しても端末内のスターが正本なので、操作はそのまま続けられます。設定画面には最終同期時刻と直近のエラーを表示します。設定と状態の保存に失敗した場合は両方の削除を試み、端末内のスターは消しません。設定保存後の初回同期に失敗しても設定は有効なまま残り、エラーが表示されます。端末内のスター消去を選んだ時点の ID とスターを付けた日時を保留状態として保存し、両方が一致するスターだけを消去します。選択後に追加・再追加したスターは残り、保存や消去に失敗した場合は次の同期や設定読み込み時に再試行します。

## 暗号化

- **データ鍵**: 256ビットのランダムな鍵で、端末ファイルを AES-256-GCM で暗号化します。追加認証データにはファイルのヘッダーと `deviceId` を入れ、ファイル名の付け替えを検出します。
- **keyring.json**: パスフレーズから Argon2id で作った鍵でデータ鍵を包んで保存します。KDF のパラメータ、ソルト、鍵ID（`keyId`）を平文で持ちます。
- **新しい端末の参加**: 接続設定とパスフレーズを入力し、`keyring.json` からデータ鍵を取り出します。取り出したデータ鍵は端末内の安全な保存領域に置き、パスフレーズ自体は保存しません。
- **最初の端末**: `keyring.json` がなければ作成します。2台が同時に作成した場合に備え、作成後に読み直し、別の鍵があればそちらを採用してから端末ファイルを書きます。
- **パスフレーズの変更**: データ鍵を包み直して `keyring.json` だけを書き換えます。端末ファイルは作り直しません。
- **パスフレーズを忘れた場合**: 同期データは復元できません。同期をリセットして同期先の `stars/` を作り直します。端末内のスターは残るため、リセット後に再び共有できます。設定画面にこの点を明記します。

## 接続方式ごとの実装

どちらの方式も Dart 標準の `dart:io` の `HttpClient` を使い、HTTP用の依存パッケージは追加しません。接続情報は `FlutterSecureStorage` に保存し、バックアップには含めません。HTTPS 以外の接続は受け付けません。同期先は学情や大学関連ホスト向けの `AllowedWebOrigins` に含まれないため、同期用のクライアントは許可リストを広げず、設定で入力されたホストにだけ接続します。

- **WebDAV**: URL、ユーザー名、パスワード（アプリパスワード推奨）。`PROPFIND`（Depth: 1）で一覧し、`GET`、`PUT`、`MKCOL` を使います。
- **S3 互換**: エンドポイント、リージョン（R2 は `auto`）、バケット、プレフィックス、アクセスキー、シークレット、パス形式URLの切り替え（MinIO・R2向け）。署名 SigV4 は既存の `crypto` パッケージの HMAC-SHA256 で実装し、`ListObjectsV2`、`GetObject`、`PutObject` を使います。案内では、そのバケットとプレフィックスに限定したキーの作成を勧めます。

## Google ドライブ同期（標準の方法）

利用者が用意するのは Google アカウントだけです。保存先は Drive API の `appDataFolder`（このアプリだけが読み書きできる非表示の領域）で、スコープは `drive.appdata` と、接続中のアカウントを表示するための `openid`・`email` です。`drive.appdata` は Google の分類で非機密スコープなので、必要なのは基本的な OAuth 審査だけです。

- **ログイン**: Windows/macOS は既定のブラウザを開き、端末内（`127.0.0.1`）で結果を受け取る方式（PKCE と state 付き）です。更新用トークンだけを `FlutterSecureStorage` に保存します。Android/iOS は `google_sign_in` を使います。
- **ファイル**: Drive のファイル名に相対パス（`stars/keyring.json`、`stars/devices/<端末ID>`）をそのまま使います。2台が同時に作って同名ファイルが重複した場合は、作成日時が最も古いものを正とします。
- **鍵の受け渡し（ペアリングコード）**: パスフレーズは使いません。1台目が鍵を自動で作り、`keyring.json` には鍵IDだけを置きます。2台目は、1台目の「別の端末を追加」に表示される QR（`mbgstar:` + コード）を読み取るか、コードを入力して鍵を受け取ります。コードは鍵ID・鍵・チェックサムを Base32 にしたもので、知っている人は同期データを読めます。
- **リセット**: 同期先の全端末のファイルと鍵ファイルを消し、新しい鍵とコードを作ります。他の端末は新しいコードの入力が必要になります。
- **ボタンを表示する条件**: OAuth クライアントIDを組み込んだビルドでだけ「Google ドライブで同期」を表示します。組み込んでいないビルドでは WebDAV/S3 だけが選べます。

### Drive API の上限への対策

自動保存は、単体の推定費用でソフト上限を超えるファイルを即時に見送ります（最大 2,352 MiB、約 2.3 GiB / 2.47 GB）。自動処理の各リクエストもソフト上限を検査します。

Drive API の利用量は端末ごとに「直近24時間」（1時間単位の区切り）で記録します。自動処理は、推定開始費用を加えて直近24時間で 15,000 ユニットを超える場合に止め、古い利用分が24時間の枠から外れた時点（＋最大30分のランダムな遅れ）で同期を再開します。手動操作を含め、直近24時間で 25,000 ユニットを超えるリクエストは送信しません。アプリのデータ消去や再インストール、端末の時計変更による記録の消失・ずれは、この端末内の上限保証の対象外です。

直近24時間で数えるので、Google の集計日を含むどの24時間を取っても、1台の利用量はハード上限 25,000 ユニット以下です（ローカル日付で区切ると、日付の変わり目をまたいで1集計日に最大2日分を使えてしまうため、この方式にしました）。そのため、400,000,000 ユニットの1日の無料枠には、毎日ハード上限まで使う端末で約 16,000 台、ソフト上限までなら約 26,000 台まで収まります。プロジェクトを使う他のアプリや端末がある場合は、それらも合算します。Google Drive の各リクエストは送信前に計上し、再試行も数えます。files.list は 100、files.get のメタデータは 5、alt=media は 200、create/update/delete は 50、再開可能アップロードのセッション開始・各チャンク・状態確認はそれぞれ 50 です。WebDAV/S3 は対象外です。

この端末内の上限は、正直に動くアプリに対する歯止めです。端末の時計を24時間以上進めると直近の利用分が数えられなくなるなど、端末側の操作で回避できる余地は残ります。そもそも OAuth クライアントIDは配布アプリに含まれ誰でも取り出せるため、意図的な使い込みは端末側では防げません。プロジェクト全体の最後の守りは Google Cloud 側の設定（課金アカウントを紐づけない、割り当ての上限を無料枠より低く設定する）です。

起動時・復帰時の同期は 0〜90 秒に分散し、ローカル変更があれば待機を打ち切ります。Google Cloud プロジェクトには課金アカウントを設定せず、コンソールで設定できる場合は無料枠未満のクォータ上限を設定して、超過要求を拒否する運用を推奨します。2026 年の課金詳細が Google から公表された後、これらの設定と超過時の挙動を確認する必要があります。

- **1回の同期を軽くする**: 一覧取得は通常1回の同期につき1回だけにし、鍵ファイルと端末ファイルの有無・更新はその一覧で判断します。鍵ファイルは更新番号が変わったときだけ取得し、他の端末のファイルも変わったものだけを取得します。自分のファイルは内容が変わったときだけアップロードします。
- **頻度を抑える**: 起動時と復帰時の同期は、前回の同期から2分以内なら省き、1台につき1日120回までとします。ローカル変更は5秒待ってまとめて送ります。
- **断られたら控える**: 混雑やサーバーエラーで断られたら1分間は同期を控え、続けて断られるたびに2倍（最大60分）にします。その間の変更は記録し、控える時間が明けたら送ります。

[Drive API の使用量上限](https://developers.google.com/workspace/drive/api/guides/limits)

### OAuth クライアントの設定（メンテナー作業）

- Google Cloud で External の同意画面を作成し、`drive.appdata`、`openid`、`email` を設定して本番公開します。
- Desktop クライアントを作成し、Windows/macOS のビルド時に ID とシークレットをそれぞれ `--dart-define=GOOGLE_OAUTH_DESKTOP_CLIENT_ID=...`、`--dart-define=GOOGLE_OAUTH_DESKTOP_CLIENT_SECRET=...` で渡します。インストール型アプリのシークレットは、Google の扱いでも機密ではありません。
- Android クライアントはパッケージ `net.yoshida.morebettergakujo` と、リリース用・デバッグ用それぞれの署名鍵の SHA-1 で登録します。
- iOS クライアントはバンドル ID `net.yoshida.morebettergakujo` で作成し、ID を `--dart-define=GOOGLE_OAUTH_IOS_CLIENT_ID=...`、逆順 ID をビルド設定 `GOOGLE_REVERSED_CLIENT_ID` に指定します（既定値はダミーの `com.googleusercontent.apps.unset`）。

## 実装時に決めたこと

- **同期しない間のアカウント変更**: 別のログイン ID に変えて元に戻した場合も、次の同期前にローカルのスターを残すか破棄するか選びます。メッセージ ID がアカウントをまたいで一意かは未検証のため、破棄して戻す際は端末内の本文などを再利用せず、同期レコードだけから再構築します。本文はメッセージを開いたときに補完します。
- **リセット後の旧鍵ファイル**: リセットした端末だけが削除前に確認した鍵 ID を7日間記録し、遅れて書き込まれた他端末の同じ鍵 ID のファイルを削除します。ヘッダーは未認証のため、記録した ID との完全一致に限り、削除直前に再取得して確認します。再取得と削除の間には競合の余地が残ります。自分のファイルや別の鍵 ID のファイルは対象外です。鍵ファイルを読み取れない場合もリセットできますが、旧鍵 ID は記録できません。
- **暗号ライブラリ**: 純粋な Dart 製の `cryptography` を使います（XML の解析には `xml`）。Argon2id（19 MiB・2回）は開発機の `flutter test` で鍵の作成が約0.14秒、取り出しが約0.09秒でした。UI を止めないよう別 isolate で実行します。モバイル実機での時間は未計測です。
- **アカウントの取り違え防止**: ローカルのスターの扱いを選ぶ前の保存済みログインIDから作ったハッシュを設定完了まで照合し、同期の状態と、暗号化した端末ファイルに記録します。同期のたびに、まず今のログインIDと照合します。違う場合やログインIDがない場合は、一覧の取得・マージ・端末内への反映・アップロードを一切行わず、設定画面に停止中と表示します。元のIDに戻った場合も、変更期間中のローカルの付け外しを同期に含めるか前回のマージ状態へ戻すかを利用者が選ぶまで同期しません。他の端末のファイルも、記録されたハッシュが一致しないもの（記録がないものを含む）は取り込みません。
- **設定前の端末内スター**: スターがある場合、同期に含めるか、空にして始めるかを選べます。
- **コードやパスフレーズを忘れた場合**: 確認後に同期先データをリセットして設定をやり直せます。他の端末も再接続が必要です。
- **Google の再ログイン**: ログインが切れた場合は、設定画面から再ログインして同期できます。
- **データをすべて削除**: 同期設定を読み込んで無効にし、接続方式にかかわらず Google からもログアウトします。
- **別の端末を追加**: コードの表示は Google ドライブのみです。WebDAV/S3 は接続設定とパスフレーズで参加します。
- **同期を無効にしている間の削除**: その間に外したスターは、再び有効にすると他の端末から戻ることがあります。
- **ペアリングコードのコピー**: コピーしてから60秒後、アプリの一時停止・終了時、または「データをすべて削除」の実行時に、クリップボードの内容がそのコードのままなら消去します。
- **ログイン待ちの受け付け**: 端末内で結果を待つ間は、パスが `/` で state が一致する要求だけを扱い、それ以外の要求は無視します。

# 同期先のバックアップ

同期先には端末ごとに一つのバックアップを、同期のデータ鍵で暗号化して保存します。設定画面から作成・一覧表示・復元できます。ローカルの自動バックアップ成功後は、前回の同期先への保存から24時間以上経過していれば、バックグラウンドでも保存します。復元では既存のバックアップ復元と同じ確認と処理を使います。Google ドライブを利用する場合は、全端末を失ったときの復旧に必要な「別の端末を追加」のコードを安全に保管してください。

# ダウンロードの Google ドライブ保存

任意の設定を有効にすると、Google の `drive.file` 権限を追加で求め、ダウンロードしたファイルを `More Better Gakujo/科目名/` に保存します。本人所有で共有されていないフォルダだけを使い、該当するフォルダがなければ新しく作成します。同名ファイルは共有されておらず MD5 が一致する場合に重複を避けます。端末内への保存を優先し、読み取りやアップロードに失敗した場合は画面に通知します。

## Sync storage backups and restore

Encrypted sync-storage backups contain only stars (ID, title, and starred time), and enabled favorites, portable settings, and notified-deadline keys. Download history, failed downloads, deadlines, change history, cached report lists, assignments, and drafts are excluded and ignored on restore. Uploads exceeding the 5 MiB restore limit are rejected without replacing the previous backup. Local file backups retain their existing content. Restore is bound to the account at confirmation and marks restored collections as local changes. Automatic sync-storage uploads are limited to once per 24 hours. Android Drive uploads read content URIs in chunks of at most 8 MiB.

バックアップ復元時、同期対象のコレクションはバックアップの値で上書き・追加し、省略されたキーは削除しません。バックアップ後に他の端末で追加された項目も残ります。

Drive download saving is bound to both the hash of the saved Gakujo login ID and the Google email. A download is eligible only when its account identities at the start match the binding and remain current during upload. A different Google account turns the setting off. Google sync also requires the Google account used during setup. Disabling or signing out drops pending uploads and aborts the active transfer. Legacy toggle values are migrated to secure storage without an account binding, so they require explicit re-enabling.


同期先に保存するバックアップでは、スターは ID・件名・スター日時のみを含め、同期対象で無効にしたお気に入り・設定・通知済み期限キーを含めません。レポート下書きはバックアップに含めません。同期先からスターを復元するときは、同じ ID の端末内の本文などを保持します。

When setup selects an empty start while drafts are unreadable, all stored v1 and v2 drafts are cleared at the first readable moment, before any draft is read or uploaded, regardless of savedAt.


The setup clear snapshots all registered collections, including currently disabled ones. Existing Google sync configurations without a stored Google email require disabling and setting up sync again.
